# 시각 품질 폐쇄 루프

MathCanvas 활동의 겹침·정렬·크기 문제는 눈에 띈 한 화면의 좌표만 고쳐서 끝내지 않는다. 다음 순서를 한 묶음으로 실행한다.

1. **정적 전수 검사**: released 21개 활동의 93개 variation을 실제 `renderedBounds`로 컴파일한다. 캔버스·컨테이너 이탈, 텍스트 맞춤, 선택 묶음 정렬, 보호 영역 겹침, 이동 요소와 목표 영역의 크기를 검사한다.
2. **계열별 수정**: 활동 하나의 임의 좌표 대신 공용 layout preset, 수학축, 간격 토큰, native rendered-bounds 어댑터를 고친다. 수학적 판단 → 오개념 갈등 → 불변량 확인 → 설명·수정 흐름은 보존한다.
3. **실제 화면 확인**: 변경 활동을 `verified`로 내리고 MathCanvas에서 새 canary를 만든다. 저장·재열기 뒤 핵심 정답을 실제로 옮긴 다음 선택을 해제하고, 목표 영역 이탈·이동 요소 겹침·최소 간격을 수치로 기록한다.
4. **증거 결속**: canary의 blueprint hash와 layout preset hash가 현재 코드와 모두 일치할 때만 `released`로 되돌린다. 실제 preview가 없거나 해시가 오래되면 출시는 막힌다.
5. **독립 검수**: 자동 시각 감사 점수는 계약 통과율로만 사용한다. 최종 제품 점수는 최신 보고서, 실제 preview, 변경 diff를 독립 검수자가 함께 보고 결정한다.

실행 명령은 `pnpm visual:audit`이다. 전체 출시 검증인 `pnpm check`의 마지막에도 같은 검사가 포함된다. 보고서는 `reports/VISUAL_QUALITY_AUDIT.md`와 `reports/visual-audit/latest.json`에 생성된다.

P0는 겹침·잘림·목표 미수용·오래된 canary처럼 수업 사용을 막는 문제다. P1은 배포 전 고쳐야 할 일관성 문제다. P2는 의미 전달을 해치지 않는 미감 개선이다. 테스트 수를 늘리는 것이 목적이 아니라, 시각 변경 하나가 정적 검사와 대표 실제 조작을 각각 한 번씩 통과하게 하는 것이 목적이다.
