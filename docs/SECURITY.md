# 보안 설계

## 지키는 정보

- MathCanvas `accessToken`
- 교사의 기존 프로젝트
- 교사가 승인한 활동 내용
- 로컬 브리지 연결 코드

## 보안 불변 조건

1. MathCanvas 토큰은 Chrome의 MathCanvas 페이지 컨텍스트 밖으로 나오지 않습니다.
2. MCP 서버와 AI 대화에는 토큰, Authorization 헤더, 비밀번호 필드가 없습니다.
3. 기존 프로젝트 수정·삭제 API를 호출하지 않습니다.
4. 교사가 확인한 `ActivitySpec` 해시와 실제 생성 해시가 다르면 쓰지 않습니다.
5. validator 오류가 하나라도 있으면 작업을 만들지 않습니다.
6. 로컬 브리지는 `127.0.0.1`에만 바인딩합니다.

## 로컬 브리지

- 32바이트 난수 연결 코드를 64자리 16진수로 저장합니다.
- macOS·Linux에서는 상태 폴더 0700, 연결 코드 파일 0600을 사용합니다.
- 요청마다 연결 코드와 `chrome-extension://` Origin을 모두 확인합니다.
- 최대 요청 본문은 3MB입니다.
- 응답은 `Cache-Control: no-store`입니다.
- MCP 서버 시작 로그에는 연결 코드 값을 출력하지 않습니다.
- 연결 코드는 MathCanvas 인증 정보가 아니지만 같은 컴퓨터의 다른 확장 프로그램이 작업을 가져가지 못하게 하므로 공유하지 않습니다.

## 권한

Chrome 권한은 `alarms`, `scripting`, `storage`, `tabs`로 제한합니다. 호스트는 MathCanvas와 `127.0.0.1:38471`만 허용합니다.

## 로그와 오류

민감 키 이름을 재귀 검사하고 로그용 redaction을 제공합니다. 오류 메시지에는 응답 본문이나 토큰을 넣지 않습니다.

## 승인 신뢰 모델

MCP 서버는 `draftId`, 교사가 본 `ActivitySpec` 해시, `teacherConfirmed: true`가 모두 있어야 작업을 만듭니다. 다만 MCP 프로토콜의 도구 서버는 호출한 AI가 실제 교사 발화를 정직하게 전달했는지 대화 기록과 독립적으로 증명할 수 없습니다. 따라서 교사 승인 보장은 다음 두 층으로 구성됩니다.

- 서버가 추천안과 생성 데이터의 동일성·만료·재사용을 기술적으로 검사
- Codex·Claude Code가 도구 설명에 따라 교사의 명시적 승인 뒤에만 쓰기 도구를 호출

다수 교사 배포 전에는 사용하는 AI 앱의 중요 작업 승인 정책도 함께 검증합니다.

## 알려진 제한

- 개발자 모드 확장 프로그램은 Chrome 웹 스토어 서명·자동 업데이트 보호를 받지 않습니다.
- 연결 코드는 현재 컴퓨터 사용자 계정이 읽을 수 있는 로컬 상태 파일에 있습니다.
- 내부 웹 계약은 MathCanvas 업데이트로 바뀔 수 있습니다. 불일치 시 안전하게 멈추지만 자동 복구하지 않습니다.
- v0.1은 한 번에 한 MCP 프로세스만 브리지 포트를 소유합니다.
- MathCanvas 생성 API가 별도 idempotency key를 제공하지 않아, 도구는 승인 초안·작업의 원자적 로컬 스냅샷과 고유 제목 조회로 같은 승인 재시도의 중복을 막습니다. 새 추천을 다시 승인한 경우에는 제품 정책에 따라 새 캔버스를 만듭니다. 서비스 검색 반영이 비정상적으로 오래 지연되는 극단적인 장애는 실제 운영 파일럿에서 추가 확인합니다.
