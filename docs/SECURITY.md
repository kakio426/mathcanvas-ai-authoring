# 보안 설계

## 지키는 정보

- MathCanvas `accessToken`, 쿠키와 로그인 세션
- 교사의 기존 프로젝트
- 교사가 승인한 활동 내용
- 전용 Chrome 프로필

## 보안 불변 조건

1. MathCanvas 토큰은 MathCanvas 페이지 컨텍스트 밖으로 반환하지 않습니다.
2. MCP 응답, AI 대화, 생성 작업 파일과 로그에는 토큰·Authorization 헤더·비밀번호를 넣지 않습니다.
3. 기존 프로젝트 수정·삭제 API와 일반 목적 브라우저 제어 도구를 제공하지 않습니다.
4. 교사가 확인한 `ActivitySetSpec` 해시, 문제별 `CanvasActivitySpec` 해시와 실제 생성 payload 해시가 다르면 쓰지 않습니다.
5. validator 오류 또는 최신 객체 계약 불일치가 있으면 프로젝트를 만들지 않습니다.
6. 로컬 HTTP 서버와 수신 포트를 열지 않고 stdio MCP만 사용합니다.

## 전용 Chrome 프로필

- 일반 Chrome 기본 프로필을 자동화하지 않습니다.
- 전용 프로필은 `~/.mathcanvas-ai-authoring/chrome-profile`에 저장합니다.
- macOS·Linux에서 상태 폴더는 생성 시 0700 권한을 요청합니다.
- 로그인 세션이 저장되므로 해당 상태 폴더를 다른 사람에게 공유하지 않습니다.
- 같은 프로필을 두 프로세스가 동시에 열지 않도록 Codex와 Claude Code를 한 번에 하나만 사용합니다.
- 서버 잠금 파일이 동시에 실행된 두 번째 MCP 서버를 차단합니다.

## 페이지 컨텍스트 쓰기

- Node에서 payload SHA-256을 먼저 검사합니다.
- 생성 직전 MathCanvas 페이지에서 공개 객체 계약과 로그인 상태를 다시 검사합니다.
- 페이지 안에서 payload SHA-256을 한 번 더 계산합니다.
- 같은 고유 제목이 이미 있으면 새 POST 대신 기존 프로젝트 ID를 사용합니다.
- 허용된 쓰기는 새 프로젝트 `POST /api/project`뿐입니다.
- 응답 본문 전체를 로그에 남기지 않고 프로젝트 ID 또는 정규화된 오류 코드만 반환합니다.

## 승인 신뢰 모델

MCP 서버는 `draftId`, 교사가 본 `ActivitySetSpec`의 `setHash`, `teacherConfirmed: true`가 모두 있어야 외부 쓰기를 시작합니다. 서버는 세트와 모든 문제별 payload의 동일성·만료·재사용을 검사합니다. 중간 실패 시 이미 성공한 프로젝트는 다시 만들지 않고 빠진 항목만 재개합니다. Codex·Claude Code의 도구 설명은 교사의 명시적 승인 뒤에만 쓰기 도구를 호출하도록 요구합니다.

## 알려진 제한

- 전용 프로필 파일은 현재 운영체제 사용자 계정 권한으로 읽을 수 있습니다.
- MathCanvas 내부 웹 계약은 공개 SDK가 아니므로 서비스 업데이트 뒤 도구 갱신이 필요할 수 있습니다.
- Google Chrome의 조직 정책이 Playwright 제어를 막는 환경은 별도 지원이 필요합니다.
- MathCanvas 생성 API에 idempotency key가 없어 고유 제목 조회와 로컬 작업 스냅샷으로 중복을 방지합니다. 검색 반영이 장시간 지연되는 극단적인 장애는 운영 파일럿에서 추가 확인해야 합니다.
- 손상된 로컬 상태 파일은 자동 삭제하지 않고 `.corrupt-*` 파일로 보존하지만, 그 파일의 추천 작업은 자동 복구하지 않습니다.
